## 1. 项目定位

Trae Demowall 参赛作品。三个抽中关键词构成命题，作品需同时体现三者：

| 关键词 | 类型 | 在设计中的映射 |
|---|---|---|
| 锦鲤 | 主题词 01 | 视觉主体（Canvas 程序化游动的锦鲤）+ 好运寓意（每日抽签） |
| 倒计时器 | 功能词 02 | 核心功能骨架：用户自设目标日，实时倒计时 |
| 渐变梦幻风 | 风格词 03 | 全站视觉调性：多层渐变光晕、玻璃拟态、柔光粒子 |

## 2. 产品一句话

「给自己一个值得倒数的事，然后每天领一张锦鲤签。」

## 3. 技术形态约定

- 单文件 `koi-fortune/index.html`，原生 HTML/CSS/JS，零构建、零依赖、零网络请求。
- 视觉动画使用 Canvas 2D：`#dustCanvas` 粒子层、`#koiCanvas` 锦鲤层，互不干扰。
- 数据持久化使用 `localStorage`，仅存目标日期（键 `koi-fortune.v1`）。
- 演示环境：Mac 上双击打开，断网可用。

| 2026-10-24 | 快捷日期 | 明天零点 / 一周后 / 一个月后 / 2027 元旦 / 2027 春节 + 自定义；不用「考试/面试/生日」这类没有具体日期的标签 |
| 2026-10-24 | 锦鲤渲染方案 | 22 点中轴链式跟随 + 限角速度转向（不走速度向量插值，否则像折线）；侧向波动只在绘制期叠加、不回写中轴；体宽剖面按「吻端留宽 → 36% 处肩胸最宽 → 72% 后尾柄急收」，尾鳍分两片从尾柄两侧长出 |
| 2026-10-24 | 签文信息量 | 每签补齐解签、幸运色（名 + 色值）、幸运数字、今日小贴士；签面从 4 区块扩到 9 区块。用户反馈「太素」的解法是加内容而非加装饰 |
| 2026-10-24 | 分辨率策略 | 锦鲤按 `clamp(0.48, min(W/1200,H/900), 1)` 缩放；纸签内容超出时签面内滚动；700px / 520px 横屏两档紧凑规则兜底，卡片高度必须给按钮行预留空间 |
| 2026-10-24 | 功能深度 | 用户认为当前功能偏简单，但明确「下个版本再改」；本轮不扩功能范围，只做质感与版式迭代 |

## 6. 踩坑记录

| 日期 | 坑 | 结论 |
|---|---|---|
| 2026-10-24 | 计划过粗，只有任务清单，没有画面与交互叙事，用户看不懂要做什么 | 需求阶段的产物必须包含「屏幕状态 + 线框图 + 逐态交互」，否则视为未完成 |
| 2026-10-24 | 跳过门禁直接建目录准备写代码 | 用户提出「看不懂」时，先补需求表达，不是直接给代码；任何实现动作前先确认当前阶段已准出 |
| 2026-10-24 | 锦鲤像蝌蚪：体宽剖面单锥形、最宽点落在头部 | 鱼体轮廓至少要「吻端收拢 / 肩部最宽（约 30%）/ 腰收 / 尾柄细杆」四段；尾鳍根部要沿法线错开，不能从一点插出 |
| 2026-10-24 | 导出图的锦鲤剪影先于纸签绘制，被整块盖住 | 装饰图层顺序要显式确认：画在纸签之后、文字之前 |
| 2026-10-24 | 短屏下卡片高度用 vh 直接给，翻面后按钮被挤出视口 | 弹层类布局要用 `calc(100dvh - 固定占位)`，把按钮行与间距算进去 |
